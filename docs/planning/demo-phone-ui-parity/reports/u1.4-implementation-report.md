### R-6 — A40's canonical `border-top-color` is the WRONG spelling for a one-edge bar. (CHANGED WHAT I BUILT)

A40 / the `glass-tiers.ts` docblock give the web composition as `border: 1px solid <border>` then
`border-top-color: <highlightTop>`. That is correct for a **card**, which has four borders for
the longhand to override. A header bar has a border on **one** edge, so `border-top-color`
resolves against a `border-top-width: 0` and **paints nothing at all** — a value that type-checks,
satisfies a naive style pin, and is invisible on screen. That is the same silent-erasure class
§4.3 exists for, arriving from the other direction.

The phone does not use a border for it either: it builds a real 1px `View` over the gradient
(`Header.tsx:168-175` — `position:'absolute', top:0, left:0, right:0, height:1, zIndex:1`).
`boxShadow: inset 0 1px 0 <highlightTop>` is that construction in CSS — 1px, at the top, drawn
over the background, costing no layout.

**Built:** `glassWizardHeaderBar.boxShadow`, and a pin asserting `borderTopColor` is `undefined`
so the A40 spelling cannot be "restored" by someone reading the docblock without the bar in
front of them.

### R-8 — Extending the contrast stacks to `header` is measurably INERT, so I did not. (DECIDED, with arithmetic)

The brief asks me to decide, with evidence, whether U1.4 adds a `header` ground stack to
`palette-contrast.test.ts` (U0.5's P-2, U1.1 §8.2's *"U1.4 is when it bites"*).

**No — and it is not a judgement call, it is arithmetic.** `worst()` is a `Math.min` over the
stack, so a ground can only change a row's verdict by being **lighter** than every existing dark
ground (or darker than every light one). I flattened every stop over `background #002853` with
the same WCAG 2.1 helper the test uses:

| ground | flattened | relative luminance |
|---|---|---|
| `card[1]` / `nestedCard[0]` — **the binding dark ground today** | `rgb(21,63,108)` | **0.04797** |
| `elevated[0]` | `rgb(20,62,107)` | 0.04656 |
| `sheet[1]` | `rgb(14,57,101)` | 0.03959 |
| `card[0]` | `rgb(12,54,98)` | 0.03598 |
| **`header[1]`** | `rgb(2,46,89)` | **0.02688** |
| **`header[0]`** | `rgb(0,38,80)` | 0.01965 |
| `recessed[0]` | `rgb(0,30,63)` | 0.01287 |

The header tier's *worse* stop sits **44% below** the current binding ground in luminance.
Worked through: `textTertiary #7a9fc4` measures **4.9322** on `header[1]` against **3.8704** on
`card[1]`; `textSecondary #99badd` **6.7780** vs **5.3190**. Adding either tier's stops to
`DARK_GROUNDS` changes **no** `Math.min` and therefore **no assertion's outcome** — the rows
would be decoration, and decoration in a contract file is worse than an absence because it
implies coverage that is not there. (`elevated` is the same story at 0.04656 — also inert.)

Light is the mirror: `light.header` is `rgba(255,255,255,0.98)` / `rgba(248,250,252,0.95)`,
lighter than `light.card`'s `#f8fafc` / `#f1f5f9` and far lighter than `nestedCard[1]`
`rgb(223,231,239)`, so it cannot lower a light `worst()` either.

**So the phone's omission of `header`/`elevated` is not a gap it forgot — those two tiers are
never the worst ground.** I recommend the plan record that reasoning and **close** U0.5's P-2
rather than carry it forward to U2.4 or U4.1. What is NOT settled by this arithmetic: if a
future package puts text on the header tier that lands on *no other* tier, its own floor still
wants measuring — but that is a row about a token, not about a ground stack.

### R-9 — A tooling hazard that produced a FALSE CLEAN sweep, recorded so nobody repeats it.

My first literal sweep reported `0` for all eight retired values — including `#1e3450`, which
`TabBar.tsx:75` still contains and which I never touched. Reduced:

```
$ grep -rniF '#1e3450' features/demo/ui/ | wc -l      → 0     (WRONG)
$ grep -rni  '1e3450'  features/demo/ui/ | wc -l      → 1     (right)
$ grep -c $'\x231e3450' features/demo/ui/controls/TabBar.tsx → 1
```

In this Git Bash, **`grep -F` with a pattern whose first character is a literal `#` matches
nothing and exits quietly.** Every `#rrggbb` sweep in this campaign run that way is a false
clean. **Sweep on the hex body without the `#`, and always with a positive control** — a value
you know is present, asserted `> 0` in the same run. The clean sweep in §5 below is the re-run
with that control; the hazard playbook's *"every scripted edit asserts its own pattern matched"*
generalises to scripted searches and this is the proof.

   this wave and a §6.1 hotspot. The plan already anticipates this shape: U0.5's `TOKEN_MODULES`
   enumeration names a future `controls/sheet-chrome.ts` for U4.1's sheet recipe, and
   `CaseMapPicker.tsx:5` already imports from `controls/` into `screens/`.
2. **No `TOKEN_MODULES` entry.** Every value in the module is composed through a template
   literal; it holds no raw banned literal for the scan to find. Adding a path is *"a reviewable
   act"* by that list's own docblock, and this file does not earn one.
3. **Three fragments, not one with options.** *Rejected:* `headerChrome({ edge, lit })`. Two

   shapes are the three the phone actually paints (R-5).
4. **The footer is a FLIP of the same two stops, never a second pair.** *Rejected:* spelling

   order is the same paint and keeps the relationship visible in the diff — and a pin asserts
   the two fragments carry the identical stop pair, so a re-tint that moved only one would red.
5. **`padding` written BEFORE the spread at every call site.** The recipe's keys must be the last
   word; a leftover below the spread is exactly how §4.3's erasure happens. Probe P8 proves the
   pin sees it.
6. **The consumer pin loops and then compares the bars TO EACH OTHER.** *Rejected:* one
   assertion per component. A37's failure mode is not "a bar is wrong", it is "four bars are
   each nearly right on their own screen" — per-bar assertions all stay green while the set
   fragments again. Probe P7 is that exact regression and the identity pin is what catches it.
7. **Exclusivity, not presence, for the lit edge.** *Rejected:* asserting only that
   `WizardHeader` has the shadow. Probe P4 — moving the shadow into the shared fragment, the
   "helpful" edit — would have survived that, and would have lit three bars the phone leaves
   flat.
