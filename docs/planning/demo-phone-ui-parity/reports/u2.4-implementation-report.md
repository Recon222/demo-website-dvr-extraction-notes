## 1. Refutations — brief and plan checked against source first

Nine. Each was opened at `main` / at `e11d3a4` before any code moved.

### RF-1 — The well's recipe has FIVE parts, not four. The plan's U2.4 row omits `borderBottomColor`.

The row spells *"border 1px solid rgba(0,14,30,0.75), borderTopColor rgba(0,12,26,0.55)"*. **All three
phone consumers of `GlassColors.recessed` set `borderBottomColor` to `recessed.highlightTop` as
well** — three of three, no exceptions:

```
Picker.tsx:185-186            borderTopColor: recessed.highlightTop,  borderBottomColor: recessed.highlightTop
TimePicker.styles.ts:241-242  borderTopColor: recessed.highlightTop,  borderBottomColor: recessed.highlightTop
DateTimePicker.tsx:295-296    borderTopColor: recessed.highlightTop,  borderBottomColor: recessed.highlightTop
```

That is the tier, not a typo: the well's light model is inverted (`Colors.ts:406-409`), so a lip cut
INTO a surface is in shadow at the top *and* the bottom. Porting only the top would have shipped a
well with one dark lip and one bright-navy one. `glassWell` carries both; probe **P2** kills a
revert.

### RF-2 — "The calendar's accent strip stops rendering" is a NO-OP for the demo. There is no accent strip.

```
$ grep -rn "accentStrip\|AccentStrip" features/demo   ->  0 hits
```

`GlassAccentStrip` is a `GlassBottomSheet` feature (`GlassBottomSheet.tsx:95`, `:365`), and the
phone's calendar sheet turns it off (`DateTimePicker.tsx:264`) because it was the last sheet still
rendering it. **The demo never had one.** The nearest thing, `PickerSheet.tsx:70`'s
`borderTop: 2px solid T.topHighlight`, is the *sheet tier's* 2px lit edge (U4.1's `sheetSurface`),
not a tapering rule under the header — different element, different purpose. The clause's other half
("its 1px header border stays") is `PickerSheet.tsx:84`, already present and untouched. **Nothing to
delete; nothing was.**

### RF-3 — `Dropdown.tsx:73`'s `padding: '11px 12px'` is phone-EXACT and needs no change.

## 4. The I-4 decision — the general `buttonStyle` adoption scan is DECLINED, with evidence

The W2 integration report names U2.4 as I-4's trigger and asks for a decision with evidence. **I
declined the general scan and closed the measured hole behaviourally instead.** Three measurements:

1. **The proposed predicate does not select the class it guards.** I-4 suggests *"no file under
   `screens/` sets `border` + `background: 'transparent'` on a `<button>` without spreading
   `buttonStyle`."* Run over `features/demo/ui/**`, it selects **8 sites, of which zero are outline
   CTAs**: two checkbox wrappers (`ExportCaseCard:67`, `:154`), the location-row pressable
   (`ExportLocationRow:33`), a dashed add-row (`_shared:632`), a map control, an OCR chip, a map
   back-chip, and one site that already spreads `buttonStyle` (`AudioRecorderScreen:503`).
2. **A general predicate needs a ~118-entry allowlist.** 179 `<button>` elements under `ui/` against
   61 `buttonStyle(` call sites. An allowlist that size is a change-detector, not a pin
   (mutation-testing anti-pattern 2), and the allowlist itself becomes the thing that rots.
3. **Half the hole is already closed, and I-4 missed it.** `glass-tokens.test.ts`'s BANNED list
   already bans **every colour `buttonStyle` paints**: `#b8d4f0` (`:181`), `#1F6B99`/`#17527A`
   (`:184-185`), `#b72136` (`:177`), `#0e3965` (`:172`), `#2e5f97` (`:175`). A consumer that
   hand-rolls the **current** recipe reds today. Only a revert to the **pre-port** literals was
   invisible — which is exactly what probe U2.2-out did.

So the residual is narrow and specific, and it is closed where it was measured: a **render pin** on
`TimeOffsetScreen`'s two outline buttons (`time-offset-advisories.test.tsx`), asserting they paint
`buttonStyle({variant:'outline'})`'s colour and edge and explicitly **not** `#4BA3D4`/`#2B8CC1`.
Probe **P1** replays U2.2-out exactly and it now KILLS. The rest is proposed as deferral **D-2**.

**My own four recipes DO ship an adoption scan** (`choice-controls.test.tsx`), on an ARIA-role
predicate rather than a colour needle, with two named exemptions and a third test that fails on a
*dead* exemption. Its known limit, stated in-source: a hand-rolled control that declares **no role at
all** is invisible to it — which is precisely what `TimeTypeButton` was, and why the scan reported
two offenders and not three.

## 7. Deviations and deliberate choices — do not re-flag

- **`glassWell` is longhands-only while `glassCard` next to it is not.** RF-9. The ruling assigns
  changing the card fragments to the W1 seat.
- **`overflow: 'hidden'` is not in the fragment**, though all three phone sites set it. Layout, not
  paint; neither card fragment carries a layout key. `TimeWheel` keeps its own.
- **The drum's drop shadow is not ported.** One of three sites has it, and RN's five shadow props do
  not map to CSS at a fixed ratio.
- **The Dropdown LABEL line is untouched** (13 vs the phone's `fontSize.sm`, `marginBottom: 6` vs
  `spacing.xs`, `T.textDim` vs `colors.text`). A73's Delta names the alphas, the ground and the
  footers, not the label; and `T.textDim` is a demo-wide form-label colour shared with
  `DateTimeField`, `RequestedScopeScreen` and `DvrInfoScreen`. Moving one makes it inconsistent with
  its neighbours in the same form. Deferral **D-3**.
- **`justifyContent: 'center'` is not ported to the DATE/TIME triggers.** Inert at current content
  (~49 px against a 44 floor), and adding `display: flex` to make it work changes how
  `textAlign: 'left'` resolves.
- **Picker footers were already done by U2.2** and are left alone. Verified variant-for-variant:
  `TimePicker`'s pair is `primary`/`secondary` (`TimePicker.styles.ts:7-9`, `:84-86`) and the
  calendar's Done is `primary` (`DateTimePicker.tsx:276`); the demo matches all three.
- **A23 (`colors.disabled`) needed no work here.** D10 restricts the token to where the phone paints
  a *fill* (Button — U2.2's). This package's disabled states stay `opacity` + `aria-disabled`; only
  the *value* moved, `0.4 → 0.5`, to the phone's (`Checkbox.tsx:106-108`).
- **`ExportLocationRow`'s `borderRadius: 11` stays** rather than becoming `radius.full`. Identical
  render on a 22 px box; demo §0.4 forbids tidying lifted values for no visual delta.
- **`RadioOption`/`CheckboxBox` take no `disabled` prop.** See §8.

## 8. Invalid states — enumerated
