## 2. What landed

### 2.1 `SEAM(U3.2)` — `ui/tokens/status.ts`

```ts
export type StatusSeverity = 'info' | 'warning' | 'success' | 'error'
export const SEVERITIES: readonly StatusSeverity[]
export const STATUS_SEVERITY: Record<LocationMapStatus | 'incident', StatusSeverity>   // as const satisfies
export const STATUS_ACCENT:   Record<LocationMapStatus | 'incident', PaletteToken>     // as const satisfies
export interface SeverityTone { background; borderColor; color; accent }
export function severityTone(severity: StatusSeverity, s?: ColorScheme): SeverityTone
export function neutralTone(s?: ColorScheme): SeverityTone
export const NEUTRAL_TINT_ALPHA = 0.15
export type StatusBadgeSize = 'small' | 'medium' | 'large'
export function statusBadgeStyle(tone: SeverityTone, size?: StatusBadgeSize): CSSProperties
```

**Invalid states, and how each is made unrepresentable or pinned** (the max-tier duty):

| Invalid state | How it is closed |
|---|---|
| a severity with no `*Light` / `*OnLight` pair (e.g. `primary`) | **Unrepresentable.** `severityTone` indexes `` c[`${severity}Light`] `` — a fifth member of `StatusSeverity` without the token trio is a compile error at that line, not a runtime `undefined`. This is the phone's `working → info, not primary` ruling enforced by the type system rather than by a comment |
| a new `LocationMapStatus` nobody rules on | **Unrepresentable.** both tables are `as const satisfies Record<LocationMapStatus \| 'incident', …>` |
| the two tables disagreeing (`complete`'s accent being `warningAccent`) | **Pinned**, through the recipe, in both schemes — `status.test.ts` "keeps the two tables in step" |
| `neutral` posing as a severity | **Unrepresentable.** `neutralTone` is a separate function; `'neutral'` is not in `StatusSeverity`, so it cannot reach `` `${severity}Light` `` |
| the accent painting TEXT (1.92–2.24:1) | **Pinned twice** — `status.test.ts` ("never hands the saturated accent to the foreground", both schemes) and `DashboardScreen.test.tsx` at the render |
| a `*OnLight` foreground painting a BARE MARK (dE 0.0 in dark) | **Pinned** — `DashboardScreen.test.tsx` "paints both BARE MARKS with the accent" |
| any text-on-fill below AA 4.5 (A19's rider) | **Pinned** — `palette-contrast.test.ts`, level × scheme cross product plus the neutral over every ground |
| a translucent fill (unmeasurable ratio) | **Pinned** — `status.test.ts` "paints an OPAQUE fill" asserts `/^#[0-9a-f]{6}$/i` for every level × scheme |
| a shorthand erasing a border side | **Unrepresentable in the recipe** (no `border` key) and **pinned** — `status.test.ts` `not.toHaveProperty('border')` |

**Emphasis × level × scheme** is therefore total and closed: 4 levels + neutral, 2 emphases
(`fill` via the trio, `mark` via `.accent`), 2 schemes — every cell either resolves through
`palette[s]` or is a compile error.

## 7. Deferral PROPOSALS

`dt-review-aggregator` is the sole writer of `docs/code-reviews/deferred.md`. These are proposals.

**D-1 · The engine still decides colour-shaped things through a UI-owned vocabulary.**
- **Source:** U3.2 commit `54833a1`; `features/demo/CLAUDE.md` (engine purity); plan §2.
- **What:** `recorderStatusTone` and `levelFillBand` are enums the UI maps, which is right — but
  `engine/logic/ocr.ts:275-280`'s `getConfidenceLevel` still returns a `color: string` on its
  `ConfidenceTier`, so the engine has not stopped holding colour, it has stopped holding *some*
  colour. Four hexes remain there, including `#ff7a45`, a fifth accent hue the matrix never names.
