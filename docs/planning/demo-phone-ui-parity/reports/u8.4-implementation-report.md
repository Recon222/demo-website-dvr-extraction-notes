## 6. Two likely defects (as the brief requests)

### DEFECT 1 — `printType` has no INTERSECTION branch, so four `.d.ts` reference names they never define

`gen-dts-props.mjs:110-156` handles arrays, booleans, unions, call signatures and local object
types, but **not intersections**. `SubmissionScreen`'s `coordinates?: GpsCoordinates & { source:
GpsSource }` therefore falls through to `clean(type.getText(node, FMT))` and emits the bare names.
Surfaced only because R-2's fix un-froze the config; scanning the regenerated `dtsPropsFor` for bare
capitalised identifiers finds five real dangles beyond the DOM-lib ones (`PositionOptions`,
`MediaStream*`, which the design tool's tsc has):

| component | undefined names |
|---|---|
| `SubmissionScreen` | `GpsCoordinates`, `GpsSource`, `ReverseGeocodeResult` |
| `NewLocationModal` | `GpsCoordinates`, `GpsSource`, `ReverseGeocodeResult` |
| `OcrCaptureScreen` | `OcrRecognizeOutcome` |
| `NewCaseModal` | `NewCaseFields`, and a bare generic param `K` |

`all .d.ts parse cleanly` still passes, so this is contract QUALITY, not a build break — and it is
strictly better than the frozen 3-prop entries it replaced (the props did not exist there at all).
`NOTES.md`'s "Result: **zero unresolved type references**" claim is no longer true and the corrected
text says so. Fix is one arm beside the union branch:
`if (type.isIntersection()) return type.getIntersectionTypes().map(t => printType(t, node, depth)).join(' & ')`.
Not taken here: it changes a generator's output shape for 37 components at the closing package.
Proposal D-1.

### DEFECT 2 — the previews are not typechecked AT ALL, which is why §4.1's ten cards could rot silently

Previews import `'open-pro-next'`, which resolves at bundle time via the converter's redirect and
**never** for tsc — `NOTES.md`'s calibration notes tell authors to ignore the "Cannot find module"
diagnostic. So the entire preview corpus is untyped against the components it renders, and the ONLY
thing that catches prop drift is a Playwright render check that (a) requires a full bundle build,
(b) cannot run in `pnpm test`, and (c) nothing triggers on a component prop change. Ten empty cards
is the measured cost. The durable fix is a generated ambient declaration —
`declare module 'open-pro-next' { export { Banner } from '…' }` emitted from `componentSrcMap`
alongside `ds-entry.ts`, plus `.design-sync/previews` in a tsconfig that sees it — which would turn
this whole failure class into a compile error at zero runtime cost. Proposal D-2.

## 7. Deferral PROPOSALS (house format; `dt-review-aggregator` decides and writes)

### D-1 — `gen-dts-props.mjs` cannot print intersection types

**Source:** U8.4 implementation, Defect 1.
**What:** `printType` (`gen-dts-props.mjs:110-156`) has no `isIntersection()` arm, so
`GpsCoordinates & { source: GpsSource }` prints as bare names. Five repo-local names
(`GpsCoordinates`, `GpsSource`, `ReverseGeocodeResult`, `OcrRecognizeOutcome`, `NewCaseFields`, plus
a leaked generic param `K`) are undefined in four emitted `.d.ts`.
**Why deferred:** it is a strict improvement on the frozen state it replaced (those props were
absent from the contract entirely), `all .d.ts parse cleanly` passes, and changing a generator's
output shape for 37 components belongs in a package with a review round after it — U8.4 is the
closing package of W4.
**Trigger:** **the next design-sync re-sync that reports `[DTS_PARSE]` or an unresolved-reference
warn**, or the next package that edits `gen-dts-props.mjs` for any reason — whichever first.

### D-2 — the design-sync previews are outside every typecheck

**Source:** U8.4 implementation, Defect 2.
**What:** previews import `'open-pro-next'`, unresolvable to tsc, so 37 preview files are untyped
against the components they render. Measured cost: 10 of 37 cards rendering EMPTY, undetected until
this package built the bundle.

`componentSrcMap`) plus a tsconfig change that widens the program to `.design-sync/` — a
build-configuration change with its own blast radius, at the closing package, with the immediate
damage already repaired.
**Trigger:** **the next time a synced component's props change** (the guard that would have caught
it does not exist), **or** the first W5/post-campaign package that touches `.design-sync/` tooling.
Interim mitigation is in place: `NOTES.md`'s new "The render check is the ONLY guard on
preview↔component prop drift" section instructs rebuild-and-revalidate on any prop change.

## 9. For whoever comes next — consume-me

1. **`ds-bundle/` is gitignored and NOT on this branch.** Rebuild before the remote push (§5).
2. **The `.ds-sync` toolkit lives only in the MAIN checkout and is gitignored.** In a worktree you
   need TWO junctions: `.design-sync/node_modules` → `<main>/.ds-sync/node_modules` (this one is
   what makes ESM resolve `ts-morph`; **`NODE_PATH` cannot do it — it is CommonJS-only**, and the
   build recipe's `NODE_PATH` line misleads on exactly this) and `.ds-sync` → `<main>/.ds-sync`.
   Tear the worktree down ONLY with `tools/worktree-remove.ps1` — a recursive delete follows those
   junctions into the main checkout.
3. **Any change to a synced component's props requires a rebuild + re-validate.** The suite cannot
   cover it (Playwright + full build). `ds-bundle/.render-check.json` carries per-component
   `firstErr`. This is now written into `NOTES.md` as its own section.
4. **Four guards are now driven from `config.json`** — entry resolution (per component), `cardMode`
   coverage, `dtsPropsFor` coverage with no orphans, and preview existence + retired-hex freedom. A
   38th component is covered with no test edit, but it WILL red until its preview exists and both
   generators have run. That is the point.
5. **`NOTES.md`'s "zero unresolved type references" is no longer true** (Defect 1) and the file says
   so. Do not re-assert it without re-running the scan.
6. **`previews/` is SHARED with `config.marketing.json`.** 21 `(stale preview: …)` lines in a demo
   build are the marketing previews and are informational. The retired-hex sweep walks the directory
   WHOLE with no exemptions — if a marketing preview ever legitimately needs one of those hexes, the
   exemption is a deliberate edit to `palette.test.ts`, not a silent pass.
7. **Previews cannot import the token modules** (they resolve `'open-pro-next'`, which exports only
   pinned components). Every colour in a preview is a literal with a `file:line` citation, held only
   by the sweep. There is no way around this short of exporting tokens through the bundle.
