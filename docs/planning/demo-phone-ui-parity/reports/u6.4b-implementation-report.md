## 5. Two likely defects

**1. The summary card is now `nestedCard` with no glass parent (`CompletionScreen.tsx`).**
The phone's summary card is nested INSIDE `<FormSection title="Case Summary" glass>`
(`completion.tsx:532-533`), so `nestedCard`'s lower alphas read correctly as subordinate. The demo
has no such wrapper — the card sits directly on the screen ground, and the `SectionCard` beneath it
is a full `glassCard`. The result may read as an inverted hierarchy: the most important panel on
the screen painted one tier *below* the form section under it. A contrast ratio is structurally
blind to this — it is the "cards on cards read flat" class GATES §13 reserves for the owner device
pass. I implemented the named ruling (matrix row 46 says `nestedCard` in so many words, and the
phone's tier confirms it) rather than substituting my own judgement. **Two candidate fixes if the
device pass agrees it reads wrong:** (a) wrap the card in a `SectionCard title="Case Summary"`, the
phone's structure exactly, at the cost of a heading the demo never had; or (b) keep `glassCard` for
it and record M1(a) as tier-inapplicable on this side. **My recommendation is (a).**

**2. `Banner`'s assertive live region now fires on two more surfaces.**
The DST advisory was `role="status"` (polite) and is now `role="alert"` + `aria-live="assertive"`;
`CompletionScreen`'s no-case banner is new and also assertive. Both are correct by the phone's own
routing and by `FieldError`'s ruling (a message raised by a deliberate act), and the mutual
exclusion on Completion is ported precisely because the phone measured two assertive regions
cutting each other off. But the DST advisory re-renders whenever its inputs change, and
`time-offset-advisories.test.tsx` has a case pinning that it recomputes only on its own inputs —
so a visitor toggling DVR-Applies-DST repeatedly will hear it re-announced each time. Not
regressed by this package (the message already re-rendered), but newly *audible*. Worth one listen
in the device pass.
