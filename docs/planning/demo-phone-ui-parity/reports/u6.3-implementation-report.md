## 4. Decisions and justified deviations

1. **`footerWrap`'s opaque `colors.background` (phone `:313-315`) NOT ported.** It backs an
   `Animated.View` floating over a `FlatList`. The demo's footer is a `flex: 0 0 auto` sibling of
   its own scroll container, so nothing passes behind it for the tier's 0.95/0.98 alphas to
   reveal, and no other demo bar carries a ground. Reason in-file.
2. **`ExportCaseCard` stays ONE element where the phone needs two** — the `masksToBounds` record
   the row asks for. CSS paints `box-shadow` outside the border box and `overflow: hidden` clips
   only descendants, so the split would be an empty div. The phone's *second* reason (an opaque
   fill so Fabric takes the cheap `shadowPath` instead of rasterising cards on scroll, `:250-257`)
   is the more dangerous half to port blindly — it would put solid navy under this card's own
   alpha-0.85 gradient, and the phone documents the cost it accepts for it (its grid backdrop
   stops showing through). Both recorded in the `wrapper` docblock.
3. **The hub's empty state is NOT routed through `controls/EmptyState`** even though row 24 lists
   A80. The phone has that component at `dd5551ec` and **the hub does not call it** — it is used at
   exactly one site (`CaseList.tsx:194`) and this screen is hand-rolled (`styles.centered:295-300`
   + `styles.emptyText:301-305`). The seam's recipe is `paddingVertical: xxl` (48) plus an
   unconditional `marginBottom: lg` (24); applying it to a centred `flex: 1` fill would be a
   divergence *from* the phone wearing a seam's name. A80's three values moved instead, and an
   **exclusivity** pin asserts the seam is not adopted.
4. **`locationsContainer`'s `marginTop: spacing.base` (phone `:335`) NOT ported.** The phone's
   `card` pads uniformly at `spacing.md` and closes its header row flush; the demo's header button
   already closes with `padding: '16px 16px 16px 8px'` and spends that gap elsewhere. Adding 12
   more doubles it (§4.2 — do not tidy the lifted geometry). The 4px *below* the line **is** the
   phone's `paddingTop: spacing.xs`.
5. **`ExportLocationRow`'s `borderRadius: 11` stays**, not `radius.full` — U2.4 adjudicated it
   (its deliberate-choices item), identical rendering. Not re-litigated.
6. **Type sizes untouched** (17 / 13 / 11 / 14 / 12). §4.9 keeps the demo's off-scale sizes as
   commented literals and lists no export move. The one size that DID move — the empty state's
   16 → 18 — is on the ladder and is the phone's `Typography.fontSize.lg` at `:302`.
7. **`header-chrome.ts` not edited, and the export footer is NOT added to
   `header-chrome.test.tsx`'s `BARS` loop.** That loop asserts `decl(glassHeaderBar)` **whole**;
   this bar carries the header ground with a **top** hairline, so it would fail the `borderBottom`
   half for the right reason. Its anti-drift coverage lives in `ExportHub.test.tsx` instead,
   reading `GLASS_TIER[scheme].header.border` from the **tier**, not from the fragment.
8. **A31's lit top edge is NOT added to `ExportCaseCard` — it is ledgered.** Row 266 lists A31, but
   this card composes gradient + border only because it consumes `GLASS.gradientCardDiag` as a bare
   string rather than a fragment. That is **`deferred.md` §96**, which names
   `screens/export/ExportCaseCard.tsx:127` explicitly. See §6 — its trigger has a problem.

## 6. Deferral PROPOSALS (`dt-review-aggregator` writes the ledger — I do not)

### D-1 — `letterSpacing` has no scale, 55 sites and 17 values; the phone names three

- **Source:** U6.3 implementation. `ExportHub.tsx`'s artifact line spells `letterSpacing: 0.6`;
  phone `styles.artifactLine:326` is `Typography.letterSpacing.wide` = **0.5**.
- **What:** the phone owns exactly three (`tight -0.5`, `normal 0`, `wide 0.5`,
  `Typography.ts:44-48`). The demo has **55 occurrences across 17 distinct values** (measured,
  non-test): `0.5`×8, `2`×7, `0.8`×6, `1.5`×5, `1`/`0.4`/`0.3`×4 each, `1.4`/`1.2`/**`0.6`**×2,
  and `8`/`6`/`5`/`3`/`0.2`/`0.1` once each. Eight already sit exactly on `wide`; the two 0.6s are
  near-misses of it. `tokens/scale.ts` carries no tracking scale and A47 (§4.9) governs **sizes and
  weights only** — it is silent on tracking, and §4.3's "silence is not conflict" applies.
- **Why deferred:** fixing one site in isolation is the failure mode A37 exists to name — a value
  that is *nearly* right on its own screen. The 17 values span two unrelated idioms (sub-1px body
  tracking vs the 2–8px display tracking on splash/terminal/scanner chrome), and deciding which
  collapse onto `wide` needs the same census-then-ratify pass every other A-row got. Doing it from
  a surface package would open ~20 files that six later packages hold.
- **Trigger:** **U8.2's literal sweep** — the last package whose row is already a cross-cutting
  census, and the first point at which every owning package has closed. Fires earlier if any
  package proposes a `Typography.letterSpacing` port, or on the first observed tracking drift
  between the repos. If U8.2 declines it, the backstop is **the owner's D1 device pass**, where
  0.5-vs-0.6 on a mono readout is legible side by side.

### D-2 — the demo has no press-feedback idiom, so `opacity: 0.7` cannot be ported at all

- **Source:** U6.3 implementation. `ExportLocationRow` (phone `:112-114`, `styles.pressed`),
  `ExportCaseCard` (phone `:296-298`, same value on `headerPressable`).
- **What:** RN delivers this through `Pressable`'s `({ pressed })` style callback. The web
  equivalent is `:active`, a **selector** — and `features/demo/CLAUDE.md` scopes `ui/demo.css` to
  globals + keyframes, with everything else inline `CSSProperties`. Measured: **no `:active` rule
  and no press-opacity idiom exists anywhere in `features/demo/ui`**, so this is not these two
  components' gap. A75's canonical recipe names `press feedback opacity 0.7` explicitly, so it is
  an unmet clause of a ratified row, not an invention. The **disabled** half of the same pair
  (`opacity: 0.5`) is state rather than a pseudo-class and is already ported at both sites.
- **Why deferred:** the decision is architectural and belongs above a surface package — either one
  `demo.css` rule keyed off a shared `data-*` attribute (which puts paint outside the inline-style
  rule the whole demo is written to), or a per-component `useState` press handler (which is
  behaviour, and D20's carve-out does not name U6.3 for it). Either way it lands at ~40 controls
  at once or it recreates the four-nearly-right-bars failure.
- **Trigger:** **U8.3's control sweep**, the only remaining package that opens the shared control
  layer wholesale — it either adds the idiom once and adopts it, or records that the demo
  deliberately ships without press feedback so A75's clause stops reading as outstanding. Fires
  earlier if any package needs `:active` for another reason. **If neither happens, A75 cannot be
  marked COMPLETE** — that is the concrete consequence, and it is checkable at U8 exit.
