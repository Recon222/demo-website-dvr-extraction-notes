## 4. Decisions and justified deviations

**4.1 · The seam is a style CONST, not a `FieldLabel` component.** `tokens/field-input.ts` already
owns A72's box half as a spreadable style; the label half joins it in the same shape at the same
address, which is rung 2 of the ladder (reuse the pattern that is here) and needs no new file and
no new import edge from `inputs/` into `screens/`. The required asterisk is deliberately NOT
exported: it is one `<span>` at the two sites that take a `required` flag, and both already name
`colors.error`, so a second export would add a hop and remove no duplication.

**4.2 · `FieldError` IS a component, and the asymmetry is deliberate.** The error line carries a
glyph and an id-and-role contract; the three alert-site callers need all of it and would each
re-derive the SVG otherwise. `BannerIcon` (U6.2's export, offered in its consume-me item 4 for
exactly this) could not serve it: it is hard-wired to `iconSize.sm` (20), which is a callout's
glyph, and the field line takes `iconSize.xs` (16) beside 14px text. Adding a `size` prop to
`BannerIcon` to unify five sites was the alternative and was rejected as the larger diff across a
merged W2 seam.

**4.3 · Both `CoordinateField`s were fixed, but NOT merged.** `NewCaseModal.tsx:54-85` and
`inputs/IncidentLocationFields.tsx:88-133` are 95% identical — same wrapper, same
`fieldInputStyle({error,focused})`, same on-blur parse — and have been forked since P3. Merging
them means picking one error contract (internal state vs `error` prop) and rewiring the other
caller, which is a structural change in a package whose row says "adoption only". The shared
RECIPE is unified; the components are not. Deferral proposal 3.

**4.4 · The blocked-reason lines override exactly one key, `marginTop: 0`.** They hang off no
field box, and the `Field` above them already ends in `spacing.md`. `FieldError`'s `style` prop is
documented layout-only, the same contract `Banner`'s carries and for the same reason.

**4.5 · No pin was written for the `#99badd` clause, and none should be.** See R-5.

## 9. Two likely defects (asked for by the brief)

**Defect 1 — `FieldError`'s `role` is optional, and the two call sites that omit it are correct
for a reason no type can carry.** Omitting it is right ONLY because those two lines are already
inside an unconditionally-rendered `role="status"` region. A third caller that omits `role`
outside such a region gets a validation message that **announces nothing at all** — visually
identical, silently inert to a screen reader, and green in every test that does not specifically
look for the role. `field-recipe-sweep.test.tsx` pins the two current omissions as correct, which
means the suite actively documents the omission as a legitimate shape. The honest fix is a
required discriminant (`live: 'alert' | 'inside-region'`) so the choice cannot be made by
forgetting; that is a type change to a seam this row created and I did not want to over-fit it to
two callers. **Watch:** the third `FieldError` caller, and any package adding a validation message
to a surface that is not already a live region.

**Defect 2 — the label seam is a shared mutable-looking object, and one caller already
demonstrates the shape that breaks it.** `fieldLabelStyle` is a `CSSProperties` const passed
directly as `style={fieldLabelStyle}` at seven sites — React does not mutate it and `tsc` does not
freeze it, so a caller that ever writes `fieldLabelStyle.color = …` (rather than spreading) would
restyle every form label in the product from one file, with no test naming the offender. Nothing
does this today. The near-miss is real though: `UserProfileModal` had `const labelLine:
CSSProperties = fieldLabelStyle` for one intermediate edit before I collapsed it to a direct read,
and an aliased const is one keystroke from an aliased mutation. `fieldInputStyle` is immune by
construction (it is a function returning a fresh object); this one is not, and the asymmetry
between the two halves of the same seam is the thing a reader will not expect. **Watch:** any
caller that assigns `fieldLabelStyle` to a local, and any `Object.assign(fieldLabelStyle, …)`.
