### R-7. The coordinator's lit-edge prescription is half right, and the wrong half is measurably worse.

The mid-task instruction was *"three side longhands, no shorthand after a spread."* Clause 2 is
correct and is the consume-me rule. Clause 1 is refuted by measurement.

| Form | first paint (top / side) | after a consumer's `{ ...f, borderColor: 'rgb(1,1,1)' }` |
|---|---|---|
| three side longhands (`borderTopColor`, `borderRight/Bottom/LeftColor`) | `rgba(184,212,240,0.14)` / `rgba(28,78,132,0.6)` | **`rgb(1,1,1)` / `rgb(1,1,1)` — LIT EDGE LOST** |
| shipped (`borderStyle`, `borderWidth`, `borderTopWidth`, `borderColor`, `borderTopColor`) | `rgba(184,212,240,0.14)` / `rgba(28,78,132,0.6)` | **`rgba(184,212,240,0.14)` / `rgb(1,1,1)` — edge survives** |

Why: with no `borderColor` key in the fragment, a consumer's `borderColor` is a NEW key and is
appended **last**, so it repaints all four sides including the top. In the shipped form `borderColor`
already occupies an earlier slot, and JS keeps a re-assigned key at its original position — so the
override lands there and `borderTopColor` still applies after it. The shipped form is the only one of
the three candidates that survives the exact hazard W1 raised.

Falsifiable, not just argued: mutating the shipped fragment INTO the prescribed form is **KILLED** by
this package's own suite (probe T1, §4), with the hazard's own message —
`expected 'rgb(1, 1, 1)' to be 'rgba(184, 212, 240, 0.14)'`.

## 3. Decisions, and the alternative rejected

1. **One shell, in `controls/`, with `PickerSheet` as a preset over it.**
   Partner §3.2 is right that building beside `PickerSheet` makes a fourth sheet. The implementation
   lives at `controls/GlassBottomSheet.tsx` (the path plan §5 names and U5.3/U7.2 will import) and
   `inputs/PickerSheet.tsx` becomes ~90 lines of picker chrome. *Rejected:* keeping the implementation
   in `inputs/` with a `controls/` alias — it would have `screens/_shared.tsx` (U4.2) and the map
   filters sheet (U5.3) importing the shared shell out of the **picker library**, a layering inversion,
   and it would pull `inputs/input-theme.ts` (a U4.4-contended file) into every sheet consumer.

2. **`PICKER_SHEET_Z` moves file, keeps its name and number, and is re-exported.**
   D14 froze the number; three pins and two `_shared.tsx` docblocks read it by that name from
   `inputs/PickerSheet`. `export { PICKER_SHEET_Z } from '.../GlassBottomSheet'` keeps every import
   path byte-identical. *Rejected:* a second name (`SHEET_SCRIM_Z`) aliased to it — two names for one
   frozen number is how a frozen number drifts.

3. **Border spelled in longhands.** See R-7/R-8. *Rejected:* the `{ border, borderTop }` shorthand
   pair (correct as written, hands every consumer the hazard) and the documented escape hatch (broken).

4. **The tier's `innerShadow` is not painted.** The phone's sheet composes `Layout.shadow.sheet` and
   nothing else (`:441`; `styles.sheet :481-488` carries no shadow). *Rejected:* A40's canonical
   four-part composition for consistency — U1.4 already ruled source over doc on exactly this question
   for the header tier.

5. **The exit is timed off `SHEET_EXIT_MS`, not `animationend`.** MEASURED: this jsdom defines no
   `AnimationEvent`, and `fireEvent.animationEnd` reaches **no React handler at all** — a probe render
   logged zero `onAnimationEnd` calls for both a direct and a bubbled dispatch. An `onAnimationEnd`
   exit would be a production path no test in this repo can execute, and it hangs the sheet in a real
   browser whenever the animation is dropped. The timer duplicates nothing: one constant builds both
   the CSS duration and the timeout. *Rejected:* `animationend`; a `transitionend` variant (same
   problem).

6. **The velocity sample is floored at one frame.** Found by a flake, not by review — see §5.
   *Rejected:* dropping the velocity arm (the phone's rule has it; a permanently-zero argument is a
   lie) and faking `performance.now` in tests (moves the harness, not the defect).

7. **The scrim is announced only when `closeLabel` is passed.** The phone's shell always labels its
   scrim because it is the only dismiss affordance there. The demo's `PickerSheet` renders a labelled
   ✕, and giving the scrim the same words would put two identically-named controls in one dialog —
   which also breaks `getByRole('button', { name: 'Close' })` for the three existing picker tests.
   Passing `closeLabel` is how a caller says "this sheet has no visible close control" (A82's does
   not). *Rejected:* always announcing it (collision), and a scrim `<button>` with `tabIndex` (a
   full-bleed focusable button ahead of the dialog content is worse than RN's `accessible` semantic).

8. **`title` is required; `enableSwipeToDismiss` is in; `dismissOnBackdropPress` is out.**
   `title` is optional on the phone but every demo and phone caller passes one, and requiring it
   removes a branch. `enableSwipeToDismiss` has two **named** consumers in phone source and in the
   plan's own rows (`MediaLibrarySheet.tsx:230` → U7.2; `ExportActionSheet.tsx:112`'s `!disabled` →
   U4.2), so it is not speculative. `dismissOnBackdropPress`'s only phone user is `TimePicker`'s
   `closeOnOverlayPress`, which the demo's `TimeField` does not have — YAGNI'd, with its trigger in
   the consume-me.

9. **The picker's body/footer padding lives in the preset, not the shell.** The phone's sheet body has
   no padding (`:368-370`); content pads itself, which is why A82 gives the map filters body 16/16/8.
   The footer reads `16px 16px 4px` because the shell adds A58's `paddingBottom: 12` — 4 + 12 is the
   flat 16 those three footers rendered before, so they are unmoved to the pixel. The divider is
   demo-owned and kept: the phone's footer has no border and A58 does not give it one, so deleting it
   would be an unsourced regression on three surfaces. Same call U1.4 made for `WizardHeader`'s 56px.

10. **The phone's enter-gate (DEF-065) has no web counterpart, deliberately.** The phone holds its
    enter until the first `onLayout` because its transform interpolates against a measured
    `sheetHeight`, 0 on a mount's first open (`:180-192`). CSS `translateY(100%)` is self-relative:
    nothing to measure, nothing to gate. The un-pinnable `!isExiting` guard DEF-065 records exists
    only to protect that gate, so it has nothing to protect here.

11. **`env(safe-area-inset-top)` at `fillHeight` is NOT ported.** The phone takes `insets.top` there
    (`:421`) because its chrome can reach the status bar. Nothing inside the demo's 378×786 frame has
    one, A58 names only the bottom inset, and jsdom drops `env()` — the line would be inert AND
    unpinnable. The bottom inset IS ported (A58 names it) and is pinned on the exported constant.

## 5. The defect the flake exposed

`springs back when the drag falls short` passed and failed **by the run**. Cause: `pointermove` can
fire twice inside the same millisecond and `event.timeStamp` has ms resolution, so `delta / dt` turns
a sub-frame sample into an arbitrarily large px/s figure. A 150px synthetic move at `dt = 1` reads as
150,000 px/s and flings the sheet shut; at `dt = 0` it reads as 0.

**That is a real defect in a real browser, not a test artefact** — any pointer stack that coalesces two
moves into one millisecond dismisses a sheet the user was only nudging. Fixed by flooring the sample
interval at one frame (`MIN_VELOCITY_SAMPLE_MS = 1000 / 60`); a larger real interval is used as
measured. Pinned two-sided at the 800 px/s boundary: 13px a frame pulls, 14px flings. The suite is
deterministic over three consecutive runs.

### 8.1 The mountable shell

```tsx
import { GlassBottomSheet } from '@/features/demo/ui/controls/GlassBottomSheet'

<GlassBottomSheet

  onClose={close}                   // required. ALL FOUR routes call exactly this.
  title="Map Filters"               // required. Uppercased by the recipe; also the dialog's name.
  subtitle="3 of 8 locations shown" // optional
  closeLabel="Close map filters"    // optional — see 8.2. THE NAME IS `closeLabel` (R-1).
  headerRight={<CloseChip />}       // optional. The shell owns NO ✕ of its own.
  footer={<Row />}                  // optional. Wrapped in `paddingBottom: 12` and nothing else.
  maxHeightRatio={0.9}              // default 0.9
  fillHeight={false}                // default false — turn ON for a scrolling-list body
  showHandle                        // default true
  showAccentStrip                   // default true — form sheets pass FALSE (R-9)
  enableSwipeToDismiss              // default true
>
  <div style={{ padding: '16px 16px 8px' }}>…</div>   {/* the body pads ITSELF */}
</GlassBottomSheet>
```

Also exported: `PICKER_SHEET_Z` (31; scrim on 31, panel on 32 — **do not renumber**, D14),
`shouldDismissSheet(translationY, velocityY, sheetHeight)`, `DISMISS_DISTANCE_RATIO` (0.25),

### 8.2 Rules, each one paid for

- **`closeLabel` labels the SCRIM.** Pass it when the sheet has **no visible close control**; leave it
  off when `headerRight` carries one, or two controls in the dialog get the same accessible name and
  `getByRole('button', { name })` stops being unique. A sheet with both (the phone's media library
  does) must give them **different** wording.
- **The shell renders no ✕.** Pass one as `headerRight`, or put the action in `footer`. This is the
  DEF-UI-006 shape: the shell cannot know what it is closing.
- **The body has no padding.** Pad your own content. `fillHeight` gives the body `flex: 1` and the
  sheet a definite height — required for a scrolling list, which measures to zero in a
  content-sized column.
- **Form sheets pass `showAccentStrip={false}`** (R-9). `MapFiltersSheet` (A82) is the exception.
- **`dismissOnBackdropPress` does not exist yet.** Add it when a caller needs a non-dismissing scrim;
  the phone's shape is `dismissOnBackdropPress?: boolean = true` (`GlassBottomSheet.tsx:93`), and the
  scrim's `role`/`aria-label` must go with it.
- **Do not add a `z` prop** without ruling on D14. Every sheet paints on 31/32 today.
- **The exit needs `visible` to go false while the component stays mounted.** Unmount it and you get
  the enter only — which is what `PickerSheet` does deliberately.
