### RF-1 — Both the plan row and A72 OMIT the phone's error `borderWidth: 2`

Plan §5 U2.1 gives the recipe as
`{borderRadius:8, border:'1px solid <border>', background:'<bg>', color:'<text>', fontSize:16, padding:'16px', minHeight:44}`
with a colour-only precedence, and matrix A72's Delta lists only radius / padding / fontSize / minHeight.

The phone has a fifth geometry value neither names: `styles.inputError: { borderWidth: 2 }`
(`src/components/common/TextInput.tsx:174`), applied by the input style array at `:78-90`:

```js
const inputStyle = useMemo(() => [
  styles.input,
  { backgroundColor: colors.background, borderColor, color: isDisabled ? colors.textSecondary : colors.text },
  error && styles.inputError,                       // <- :86
  textInputProps.multiline && styles.multiline,
], [...])
```

Two consequences the row does not state and this package had to settle from source:

1. an error field's edge is **2px**, not 1px — so the recipe's border is a width AND a colour;
2. `error && styles.inputError` is keyed on **`error` alone**, not on the precedence chain. A field
   that is both disabled and in error therefore keeps the **disabled colour** and takes the
   **error width**. Transcribed exactly, and pinned
   (`tokens/__tests__/field-input.test.ts` — `borderOf({ disabled: true, error: true })`).

Safe on the web because `box-sizing: border-box` is demo-wide (`demo.css:14-17`, D9-frozen), so the
extra pixel costs no layout. **Correction owed to A72's Delta and to the U2.1 row.**

### D-1 — The text-input placeholder colour is still the browser default

- **Source:** U2.1. Plan §5 U2.1 instructs "Placeholder `textTertiary`"; phone
  `src/components/common/TextInput.tsx:121` — `placeholderTextColor={colors.textTertiary}` (`#7a9fc4`).
- **What:** every `<input>`/`<textarea>` in the demo renders the user agent's default placeholder
  colour. `grep -n "placeholder" features/demo/ui/demo.css` → no matches; there is no placeholder rule
  anywhere in the demo.
- **Why deferred:** a placeholder colour on the web is the `::placeholder` pseudo-element, which cannot
  be expressed as an inline `CSSProperties` value. The only stylesheet is
  `features/demo/ui/demo.css`, assigned to **U8.2 alone** by plan §6.1 ("If a package thinks it needs
  to touch it, that is a scope error"). §4.2 adds that jsdom renders no CSS, so the value would be
  unpinnable from vitest even if it landed. Nothing regresses in the meantime — the demo has never
  styled its placeholders, so this is an un-ported value, not a broken one.
- **Trigger:** **U8.2, at the moment it opens `ui/demo.css`.** Add
  `.demo-root input::placeholder, .demo-root textarea::placeholder { color: <colors.textTertiary> }`
  and assert it from the **Playwright** harness (§6.6), not from vitest, since jsdom cannot observe it.
  Note the token carries the documented AA ceiling M2b (dark 4.23 on `card`) — inherited, not fixed.

### D-2 — `Field`'s textarea keeps `minHeight: 76`; the phone's multiline box is 100

- **Source:** phone `src/components/common/TextInput.tsx:176-180` —
  `multiline: { minHeight: 100, paddingTop: Layout.spacing.md, textAlignVertical: 'top' }`. Named by
  neither the U2.1 row nor A72's Delta.
- **What:** the demo's textarea override (`_shared.tsx`, `{ ...boxStyle, minHeight: 76, resize:
  'vertical', fontFamily: 'inherit', lineHeight: 1.5 }`) is 24px shorter than the phone's.
- **Why deferred:** it is `Field`'s own geometry, and plan §5 assigns `Field` (`_shared.tsx:198-310`) to
  **U6.1**. Taking it here would put two packages on the same lines of the port's hottest file, which
  §6.1 exists to prevent.
- **Trigger:** **U6.1**, which owns `Field`. Either take `minHeight: 100` + `paddingTop: 16` with the
  rest of `Field`'s geometry, or record a measured divergence (the demo's textarea is `rows={3}` in a
  378px frame, which the phone's 100pt was not sized for).

### D-3 — The new focus indicator measures 2.87 against the glass card behind it

- **Source:** U2.1's `focused` branch; phone `TextInput.tsx:73` (`isFocused → colors.primary`);
  WCAG 1.4.11 (3:1 for non-text UI components); C.3 rule 4.
- **What:** the focus border is `colors.primary` `#2B8CC1`. Measured against the field's own fill
  `#002853` it is **3.94** (passes). Measured against the glass card the field sits inside — the card
  tier's two gradient stops flattened over `background` — it is **3.27** (top stop) and **2.87**
  (bottom stop). The bottom of a long form sits under the lower stop.
- **Why deferred:** the value is the phone's, verbatim, and changing it would fork the focus colour
  from the phone for a ratio the phone accepts. It is also strictly better than what shipped before
  (no focus indicator at all, an outright 2.4.7 failure), so deferring is not a regression. A fix means
  choosing between `primaryLight` (a value the phone does not use here) and a thicker indicator, which

## 10. Known weaknesses in what shipped

Stated rather than left for a reviewer to find.

1. **The de-dup scan catches the OLD recipe pasted back, not a fresh copy typed in the NEW values.** It
   is a source-text scan and inherits the string-presence trap. The durable half of the invariant is
   `field-input-recipe.test.tsx`, which drives every consumer's DOM — but a **sixth** input added in a
   future package with its own hand-rolled style would be caught by neither. The honest fix is a lint
   rule or a scan asserting that every file rendering `<input`/`<textarea` imports the seam; that would
   fire today on six out-of-scope inputs (`import/PasteStage.tsx:48`, `import/PickerStage.tsx:273`,
   `map/MapControls.tsx:120`, `NotesScreen.tsx:60`, `settings/panes/_pane-chrome.tsx`,
   `AudioPreviewScreen.tsx`), which belong to U5/U6/U7. See §11.
2. **`aria-disabled` on `SubmissionScreen`'s value `<div>`.** A bare div has the `generic` role, which
   supports no ARIA states, so the attribute is inert for assistive technology. It is what the U2.1 row
   and D10 instruct, and it matches the demo's existing spelling at `map/CaseMapPicker.tsx:112`, so it
   shipped — but it is decoration, not a working affordance. The real gap on that surface is that the
   value div has no programmatic association with its label div at all. That is U6.4a's residual.
3. **The `disabled` branch has exactly one consumer** (`Field`'s `readOnly`). If a reviewer rules RF-2
   out of scope and reverts it, the branch becomes dead code and should be deleted with it — the two
   stand or fall together.

   Case modal and confirm the list reopens exactly as it did before.
