## 1. Refutations first

Every one was opened at source. Where the plan, the matrix or the W3 legwork disagrees with the
tree or with the phone, the evidence is here and the code follows the evidence.

### R-1 — A61's "an optional centred `16/600` title" has no source. The phone's is `18/600`, `flex: 1`, LEFT.

The plan's U7.2 row and matrix A61 both state the merged target as *"an optional centred `16/600`
title in `palette.text`"*, and both say the recipe is *"stated here rather than cited"* because A61
is demo-originated. It is demo-originated in the sense that no phone component consolidates the four
overlay headers — but the phone **does** paint two of the four surfaces' titles, and it paints them
through a shared component:

| | |
|---|---|
| `src/features/media/audio-recording/components/AudioRecordingFlow.tsx:127` | `<FormLayout testID="audio-preview-screen" title="Review Audio" showExit onExit={onCancel}>` |
| `src/components/layout/FormLayout.tsx:66-76` | `FormLayout` renders `<Header title={title} showBack={!showExit} showExit={showExit} …>` |
| `src/components/layout/Header.tsx:198-201` | `title: { flex: 1, fontSize: Typography.fontSize.lg, fontWeight: Typography.fontWeight.semibold }` |
| `src/constants/Typography.ts:21` | `lg: 18` |
| `src/constants/Typography.ts:39` | `semibold: '600'` |
| `Header.tsx:88` | `style={[styles.title, { color: colors.text }]}` |

So the phone's screen-title recipe is **18 / 600 / `colors.text` / `flex: 1`, left-aligned**. `16` is
not on that path anywhere, and `textAlign: 'center'` does not appear in `Header`'s stylesheet at all.
Both 18 and 600 are on plan §4.9's ladder, so no invented step is involved either way.

**Taken:** 18/600/`colors.text`/`flex: 1`, no `textAlign`. **Consequence:** `AudioPreviewScreen`'s
title goes 20/700 → 18/600 and `OcrCaptureScreen`'s confirm title does the same. Probes P5 and P6
kill the 16 and the centring respectively.

**Same source settles the ORDER.** `Header.tsx:67-88` renders back → exit → title → menu, and
`styles.backButton`/`styles.exitButton` both carry `marginRight`. So the control is LEADING.
`AudioPreviewScreen`'s ✕ sat trailing; it moves. Probe P7r kills the old order.

### R-2 — A61's "the recorder's 40 and the camera's 48 both converge [at 44]" is wrong for the camera, and D17 forbids it.

`src/features/media/video-image-capture/components/VisionCameraScreen.tsx:775-782` at `dd5551ec`:

```
  controlButton: {
    width: 48,
    height: 48,
    borderRadius: Layout.borderRadius.full,
    backgroundColor: 'rgba(0, 0, 0, 0.4)',
```

The phone's camera control is **still 48**, and matrix row 49–55 says in its own words that
`ModeToggle`, `CaptureButton` and `RecordingIndicator` are UNCHANGED and that the demo's camera
chrome is a separate palette by design (**D17**). 44 is `Layout.touchTarget.min` — a **floor**, not a
target; 48 is `touchTarget.comfortable`. Converging the camera down to 44 would shrink a control
below the phone's on the one surface D17 explicitly freezes, and would be a worse target, not a
better one.

**Taken:** the leading control is sized per VARIANT — `glass` 44 (`RecorderScreen.tsx:281-282`,
`Layout.touchTarget.min`), `cameraScrim` 48 (`VisionCameraScreen.tsx:776-777`). Both phone-exact,
both at or above the floor. Probe P2 kills the convergence.

### R-3 — A61's "absolute row at `top:44`, `padding:'0 16px'`" generalises the CAMERA's geometry onto three surfaces that are in flow, and `16` is not the phone's number.

Two separate errors in one clause.

**(a) Positioning.** Three of the four adopters render their header IN FLOW inside a shell that
already pads 54px from the top and scrolls:

| Adopter | Shell | Header |
|---|---|---|
| `AudioPreviewScreen.tsx:109` | `padding: '54px 20px 22px'`, `overflowY: 'auto'` | in flow, `marginBottom: 16` |
| `AudioRecorderScreen.tsx` (`Shell`) | `padding: '54px 0 0'` | in flow, `padding: '0 20px 8px'` |
| `OcrCaptureScreen` confirm stage | `padding: '54px 22px 24px'`, `overflowY: 'auto'` | in flow, a bare title div |
| `MediaCaptureScreen.tsx` | full-bleed viewfinder | absolute `top: 44` |

Making the first three absolute would slide their scrolling bodies under them. **The phone agrees:**
only `VisionCameraScreen.tsx:316-326` positions absolutely (`position: 'absolute', top: Math.max(insets.top, 20) + 10`);
`RecorderScreen.tsx:284` and `Header`'s `content` are both ordinary flow rows.

**(b) The padding.** `16` is the demo's own camera literal. The phone spells `Layout.spacing.mdlg`
(**20**) at **both** counterparts — `RecorderScreen.tsx:277` (`paddingHorizontal: Layout.spacing.mdlg`)
and `VisionCameraScreen.tsx:324` (same). 20 is also what the recorder's body blocks
(`margin: '0 20px'`) and the audio preview's shell already use.

**Taken:** `OverlayHeader` writes **no padding and no position**. Placement is the caller's, through
a `style` prop with the same contract and the same wording as `controls/Banner.tsx`'s (*"Caller
LAYOUT only"*). The camera's own inset moves 16 → 20. Probes P8 (recipe grows a padding) and P9r
(caller's style loses) kill both halves.

*A note on the alternative I rejected:* giving the seam a padding and having three of four callers
override it. That is the shape §4.3 warns about — "check what the override lands on" — and it makes
the common case the exceptional one.

### R-4 — D17's TWO ruled value changes are BOTH no-ops for this codebase. The only real D17 work is the tokenisation.

**(i) `PermissionsView`'s `#007AFF` → `primaryDark`.** `partner-legwork-w3.md` W3-C5 says it is a
no-op; re-measured and it stands:

```
$ grep -rniE '007aff' features/demo/ | wc -l        -> 0
$ grep -rniE '2b8cc1' features/demo/ -l | wc -l     -> 30      (positive control)
```

And the demo's permission stage does not merely lack the hex — it already paints the ruled value:
`MediaCaptureScreen.tsx`'s grant control is `buttonStyle({ disabled: isOpening })`, whose primary
fill is `PrimaryButtonGradient.dark = [GLASS.accentFrom, GLASS.accentTo]`, and `GLASS.accentFrom` is
`#1F6B99` = `primaryDark`, since U2.2. D17 item (i) is closed by a package that landed two waves ago.

**(ii) `CameraControls`' button scrim → `colors.overlay` (90%).** This one is NOT no-op for the
reason W3-C5 gives; it is a no-op for a geometric reason, and it took reading the phone component to
see it. `CameraControls` lives in `src/features/ocr-time-capture/components/`, not in
`video-image-capture/`. Its own comment, `:131-137`:

> *"The fill is `colors.overlay` (90%), not the zone's `overlayLight` (70%): the button has to
> separate from the zone behind it AND carry an icon over whatever the camera is pointed at. At the
> old 40% black, a white icon over a bright DVR monitor measured 2.85:1 — under WCAG 1.4.11's 3:1
> floor for a non-text control. At 90% it measures 10.04:1 on the same worst case."*

Its `controlZone` (`:68`) is a full-width band **inside the full-bleed camera preview**, and the 52pt
`controlButton`s (`:72`, `:82`) sit on it, over the feed.

**The demo's OCR aim stage has no such control.** Its viewfinder is a bounded `aspectRatio` box
(`OcrCaptureScreen.tsx:508-517`) inside an opaque `#05080d` shell (`:499`); Cancel and switch-camera
sit **below** it (`:611-635`) with `background: 'transparent'` and no fill of any kind, over the
shell rather than over the feed. There is nothing whose contrast against a bright DVR monitor can be
measured, because nothing is over the monitor.

The demo's one 40%-black control circle is the **photo/video** camera's, and its phone counterpart is
`VisionCameraScreen.tsx:779`, still `rgba(0, 0, 0, 0.4)` at `dd5551ec`. Deepening it would be drift
AWAY from the phone on the surface D17 froze.

**Taken:** neither value change. The camera renders pixel-for-pixel what it rendered before; the
whole of D17's real work is the named block. Probe P4 pins that `colors.overlay` never appears on the
camera control, so a later "we forgot item (ii)" fix reds.

`u3.1-u3.4-implementation-report.md` correction 5 records that the plan's anchor for

The phone's `marginTop: spacing.md` on the MESSAGE is deliberately not ported: on the phone that 16 is
the gap under the ICON (`:61-66`), and this state has no icon. The icon itself is a deferral (D-2).

### R-9 — one prop of the media-library fold departs from the phone, and U4.1's contract is why.

The phone's call passes `closeLabel="Close media library"` (`MediaLibrarySheet.tsx:227`) **and**
renders a labelled ✕ in `headerRight` (`:194-211`). Copying both reds the suite:

```
TestingLibraryElementError: Found multiple elements with the role "button" and name "Close media library"
```

`GlassBottomSheet`'s own docblock rules the case, and it is a deliberate demo/phone difference U4.1
already recorded: *"a sheet that renders a labelled ✕ already has one, and giving the scrim the same

**Taken:** no `closeLabel`. Pinned (probe P28r), so a later "align with the phone" fix reds.

## 6. Deferral PROPOSALS (house format — `dt-review-aggregator` decides and writes)

### D-1 — the OCR guide-box mask is black where the phone's is a 60% navy wash

- **Source:** U7.2 report R-6; `features/demo/ui/screens/camera-chrome.ts` (`guideMask`, marked in-file).
- **What:** `CAMERA_CHROME.guideMask` is `rgba(0,0,0,0.6)`. Its phone counterpart,
  `src/features/ocr-time-capture/components/BoundingBoxOverlay.tsx:87`, is
  `withAlpha(colors.background, BOUNDING_BOX_UI.darkOverlayOpacity)` — the app background at the same
  0.6, inside a forced-dark subtree. The alpha matches; the colour does not.
- **Why deferred:** **D17 freezes the camera chrome** and authorises exactly two value changes,
  neither of which is this one (and both of which are no-ops here, R-4). Changing a frozen palette on
  an implementer's own reading is precisely what the freeze exists to prevent. The demo also has the
  seam ready — `withAlpha` is in `tokens/scale.ts` — so this is a one-line change whenever it is ruled.
- **Trigger:** the owner's next device checkpoint under D1 (the W3 or W4-exit side-by-side), OR any
  amendment to D17 that reopens the camera palette. Whichever fires first, re-measure and either take
  `withAlpha(palette[CAMERA_SCHEME].background, 0.6)` or record the black as a fifth named divergence.

### D-2 — the media-library empty state has no icon where the phone's does
