### R-1. The row's `dismissOnScrim` assignment is wrong for `DeleteConfirmationModal`, and following it would have shipped a behaviour regression

The U4.3 row says, in the signature cell: *"`dismissOnScrim` is the per-caller behavioural prop:
`AlertDialog` and `DeleteConfirmationModal` pass `false` (blocking semantics)"*, and again in the
recipe cell: *"`DeleteConfirmationModal`'s does not either."*

Four independent sources say its scrim **does** dismiss:

| Source | Evidence |
|---|---|
| the demo, pre-commit | `screens/DeleteConfirmationModal.tsx:96` — `onClick={onCancel}` on the scrim div |
| the demo's own docblock | `:25-28` — *"This modal's scrim DOES dismiss (`handleOverlayPress` …) — cancelling a delete by tapping away is the safe direction, and it is what the phone does."* |
| the phone | `src/features/case-management/components/DeleteConfirmationModal.tsx:43-47` — `handleOverlayPress` calls `onCancel()` whenever `!isDeleting`, wired at `:60` |
| its own test | `screens/__tests__/DeleteConfirmationModal.test.tsx:100` — *"cancels on the Cancel button, on Escape, and on the scrim — the scrim DOES dismiss here"*, asserting `toHaveBeenCalledTimes(3)` |

It passes `dismissOnScrim`. The row's own instruction — *"Do not unify dismissal behaviour — only
the shell"* — is what is being honoured; its parenthetical contradicts it. **Correction owed: plan
§5 U4.3 row, both cells.**

### R-2. `open: boolean` is dead at every call site, and adding it would have moved the focus hand-back

All three callers mount conditionally: `DemoExperience.tsx:3086` (`{deleteTarget && …}`), `:3105`
(the `exportModalMode` ternary, whose third arm is `null`) and `:3120` (`{alert && …}`);
`ExportModal.tsx:375` additionally returns `null` for `mode: 'hidden'`. An `open` prop can only
ever be `true` — the same dead weight `DeleteConfirmationModal.tsx:32-36` refuses `isDeleting`
for, in this very file set.

Worse than dead: the focus hand-back is an **unmount cleanup**. Introducing `open` would either
leave it on unmount (making the prop a lie) or move it to the `false` transition — a silent
change to when a keyboard visitor gets focus back. Dropped, with the successor path documented in
`CentredDialog.tsx`'s docblock: a dialog that wants an exit animation adds `visible` the way
`GlassBottomSheet` did, and takes the behaviour change with it.

### R-3. The signature has no `z`, and the three callers deliberately disagree

`AlertDialog` and `DeleteConfirmationModal` paint 60/61; `ExportModal` paints **40/41**
(`ExportModal.tsx:83,264` pre-commit). That is not drift — it is what lets an `AlertDialog` be
raised *over* an export overlay, which matrix B.4 row 28 (`exportNotices.ts` → `AlertDialog`) does,
and which `DemoExperience.tsx:3116` describes as intentional: *"Rendered last so it sits over every
other overlay, like an OS alert does."*

D14 rules the five z schemes OUT of this port and `UserProfilePane.test.tsx:301,315,316` pin
against renumbering. So `z` is a **required** prop; the panel paints on `z + 1`. Probe P8.

### R-4. The signature has no `describedBy`, and without it two existing pins red

`AlertDialog` and `ExportModal` both carry `aria-describedby`; `DeleteConfirmationModal` does not.
`AlertDialog.test.tsx:18-20` reads the attribute and dereferences the id; `ExportModal.test.tsx:243`
asserts `toHaveAccessibleDescription`. The row lists neither as an UPDATE, so this is an omission
in the signature rather than a preference. Added as optional. Probe P14 (KILLED, 3 tests across 3
files).

### R-5. `onDismiss?` optional beside two required gates is the one genuinely invalid state in the plan's signature

`{ onDismiss?: () => void; dismissOnScrim: boolean; dismissOnEscape: boolean }` can express *"the
scrim dismisses"* with nothing to dismiss to. `onDismiss` is **required** here. Every remaining
combination is meaningful, including `false/false` (fully blocking — nothing uses it today, but it
is exactly the shape `ProgressContent` would take if it ever adopted). See §5 for the full
enumeration.

## 5. The state space, enumerated

The brief asks for `open × stacked × reduced-motion`. `open` is refuted away (R-2), so the live
axes are **(dismissOnScrim × dismissOnEscape) × stack-depth × motion-mode**.

**Dismissal (4 cells, all valid, all reachable in principle):**

| `dismissOnScrim` | `dismissOnEscape` | Meaning | Who |
|---|---|---|---|
| false | true | OS-alert blocking: answer by choosing a button, Escape as the keyboard analog | `AlertDialog` |
| true | true | tap-away cancels | `DeleteConfirmationModal`; `ExportModal` when `!isExporting` |
| false | false | fully blocking, no escape route | `ExportModal` while `isExporting`. (`ProgressContent` is this shape and does not use the shell — §8.) |
| true | false | scrim yes, keyboard no | **nothing uses it**, and it would be a keyboard-accessibility defect. Representable; not prevented, because preventing it needs a union that `ExportModal`'s `!isExporting` gating cannot pass through without prop spreading. Flagged rather than typed out. |

**The invalid state that is now unrepresentable:** a dismissal route with no handler. `onDismiss`
is required (R-5).

**Stack depth.** Two shells can mount at once — `DemoExperience.tsx:3086` and `:3120` are
independent conditions, and `:3116` documents stacking as the *design*. Both listen on `document`,
so before this package a single Escape would have called both `onDismiss`es and the dialog
underneath would have vanished unanswered. The shell keeps a module-scope mount-order stack and
only the last entry answers. Two pins (topmost wins; the one underneath takes over when the top
unmounts), probe P9. **Known limit, written in the docblock:** the stack is mount-ordered, not
z-ordered, so a caller that mounts a lower-`z` dialog last takes the top of the stack without
being the top of the screen. No caller does; sorting by `z` would be guessing at a rule nobody has
stated.

**Motion.** `screenIn` translates 8px (`demo.css:92-95`). All three copies ran it unconditionally
— alone among this feature's entrances, which gate on `useReducedMotion`
(`GlassBottomSheet.tsx:331`, plus `ScreenStage` / `DashboardScreen` / `MediaCaptureScreen` /
`ExportHub`, named in `ExportModal.tsx:179-182`'s own comment). The shell gates. Both sides pinned;
probe P10.

## 8. Deviations from the plan, with justification

1. **Padding 16, not `20px 20px 16px`** — R-8. Two phone sources.
2. **`onDismiss` required, `open` dropped, `z` and `describedBy` added** — R-2, R-3, R-4, R-5.
3. **`DeleteConfirmationModal` passes `dismissOnScrim` (true)** — R-1.
4. **One file, not the constants-module + shell pair U4.1 shipped.** U4.1 split because U4.2, U5.1
   and U7.2 need `sheetSurface` *without* mounting the shell. No dialog consumer wants the surface
   without the shell; `dialogSurface` is exported from the same module for the day one does.
   *Rejected:* the two-file symmetry for its own sake.
5. **The shell portals; `ExportModal`'s root restructured.** §4.1 item 5 makes portalling a rule and
   `GlassBottomSheet` portals, so a consumer that forgets it re-introduces the scroll-lift bug.
   `ExportModal` now portals only its progress branch. *Rejected:* leaving the portal to callers
   (one forgotten wrapper = the bug), and nesting two portals into the same overlay root for one
   dialog.
6. **The reduced-motion gate is new behaviour** (D20 covers component-local composition for this
   package by name). The repo's own stated rule, quoted in `ExportModal.tsx:179-182`, is that every
   other entrance gates. *Rejected:* leaving `screenIn` ungated to keep the diff to "surface only".
7. **The topmost-only Escape guard is new behaviour.** Six lines. The bug is in the shared function,
   so the guard belongs there (the alternative is every future consumer re-deriving it).
   *Rejected:* a caller-side rule in a docblock; and sorting the stack by `z`.
8. **`data-alert-scrim` / `data-export-scrim` → one `data-dialog-scrim`.** Four selector lines in
   three test files. It is also what leaves U4.4 **one** site to retint instead of three.
   *Rejected:* passing each caller's legacy attribute through the shell as a prop, which preserves
   three names for one thing.
9. **`maxWidth` not ported.** The phone caps at 340 (delete) / 380 (export); inside the frozen
   378px frame the panel is 330px, so neither can bind. *Rejected:* porting a value no surface can
   render.
10. **A56 is only PARTLY closed by this package, and the part I closed is the shadow + composition
    at the dialog.** The U1.2/U1.3 report §11 already records A56 as PARTIAL with its shadow left
    to U4. `ExportActionSheet`, `PickerStage`, `TimeOffsetScreen`, `SettingsNavBar` and
    `ExportHub`'s footer also consume `gradientPanel` + `borderAccent` without the lit edge or the
    dialog cast; they are not centred dialogs and not in my Files column. Flagged, not swept.

**A finding I complied with the plan on rather than acting alone.** A45's delta gives the demo's

   in-repo precedent (U1.2's three card sites) behind it.

2. **The mount-order Escape stack is right for every caller that exists and is guessing about the
   one that does not.** "Topmost = last mounted" matches React, matches DOM paint order at equal z,
   and matches `DemoExperience.tsx:3116`'s stated intent. It diverges the moment someone mounts a
   *lower*-z dialog after a higher one — then Escape goes to the dialog underneath, which is worse
   than the pre-U4.3 behaviour of dismissing both, because it is silent. I wrote the limit into the
   docblock rather than sorting by `z`, on the grounds that sorting would be inventing a rule
   nobody has stated and that `z` is a D14-frozen caller decision. If a reviewer wants the stack
   sorted, it is one comparator and the two stacked pins already exist to catch the difference.
   The other half of this risk is that the whole guard is unreachable today — I could not construct
   a live path where two `CentredDialog`s mount together, so its pins are the only thing exercising
   it, and an unreachable guard is a fair thing for a reviewer to challenge as speculative.
