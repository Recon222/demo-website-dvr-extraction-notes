## 8. Deferral PROPOSALS

`dt-review-aggregator` is the sole writer of `docs/code-reviews/deferred.md`. These are proposals.

### D-1 — `Toggle` does not carry the phone's `marginBottom: 16`

- **Source:** matrix A76 (*"row `space-between, marginBottom 16`"*) vs plan §5 U2.3 (silent on it);
  phone `common/Switch.tsx:73`.
- **What:** the phone's `Switch` container reserves 16px below itself. The demo's `Toggle` does not,
  and this package did not add it.
- **Why deferred:** the plan row — which my brief names as the spec — omits it, and adding it would
  change 13 live surfaces to satisfy a line the executable spec does not carry. `PaneGroup`
  (`_pane-chrome.tsx:53`, `marginBottom: 20`) and `SectionCard` and two explicit wrapper divs already own that rhythm at
  all 13 sites, so the phone's margin would land *on top of* an existing one, not instead of it. The
  phone itself treats the margin as droppable — `containerStyle` exists for exactly that
  (`Switch.tsx:25`).
- **Trigger:** the owner's **wave-2 device pass** (GATES.md item 13) reports the demo's switch rows
  reading tighter than the phone's side by side. If it does, `Toggle` takes `marginBottom: 16` **and**
  `PaneGroup`/`SectionCard`'s spacing is retuned in the same commit — never one without the other.

### D-2 — `Toggle`'s 28px-tall track does not meet A49's 44px floor

- **Source:** plan §5 U2.3 cites **A49** alongside A76; matrix A49 (*"DEF-UI-019's web form: the web
  has no `hitSlop`, so a 36px painted control needs real padding or a pseudo-element to reach
  44×44"*).
- **What:** the track is 46×28. The labelled row's `padding: '4px 0'` brings the hit area to ~36; the
  two `hideLabel` hosts (`FormFieldsPane`'s grid row, `GpsCaptureControl`'s 2px-gap column) have no
  slack for more without moving their own layout.
- **Why deferred:** A76's recipe, the plan's Recipes column and the phone's `Switch` all specify the
  geometry as-is, and the plan rules it **DEMO-BETTER-by-necessity — keep the geometry**. Reaching
  44 needs a transparent pseudo-element or an absolutely-positioned expander, i.e. a new pattern
  this package was not scoped to introduce, applied at two hosts whose grids would have to absorb
  it. Doing it silently inside a "collapse four renderers into one" package is exactly the
  scope-creep the review lanes flag.
- **Trigger:** whichever package first lands the campaign's **general** web answer to DEF-UI-019's
  `hitSlop` gap (A49 names U7's `MediaPreview` 36→44 as the same class of problem, and A61's
  `OverlayHeader` converges a 40 and a 48 on 44). When that pattern exists, `Toggle` adopts it in the
  same PR; until it does, there is nothing to adopt.

### D-3 — the track scan's adjacency ceiling

- **Source:** `one-switch-renderer.test.ts` `DECLARES_TRACK`, and commit `9f6a244`.
- **What:** the geometry scan matches `46×28` only when the two keys are adjacent after the
  whitespace strip; an intervening key slips past it.
- **Why deferred:** the role scan — the first net — catches any real re-implementation regardless of
  key order, because a track with no `role="switch"` is not a switch. A proximity-window pattern
  starts matching unrelated 46/28 geometry, which trades a theoretical hole for real false positives.
- **Trigger:** a real re-drift gets through the role scan (a track re-implemented without
  `role="switch"`, e.g. as a `<button aria-pressed>`), or a reviewer finds a second `46×28` control
  in the tree. Either one, widen to a proximity window over the style object.
