### Proposal A — the RETIRED sweep's rgb-form normalizer (ledger §120's other clause)

**Source:** U8.2 implementation, refuting the brief's directive to close §120 here.
**What:** `tokens/__tests__/palette.test.ts`'s `RETIRED` needles remain hex-form only. `rgb(30,58,95)`

**Why deferred:** MEASURED, and §120's premise is wrong by fourteen: adding the rgb twins reds at

three or more of the eleven files adopts `teal-purge.test.ts`'s `canonicalTeals` shape for RETIRED in
the same commit** — whichever first. §120's own "the next commit that retires a palette value adds the

### Proposal B — `PhoneFrame`'s scan sweep ignores `prefers-reduced-motion`

**Source:** U8.2 implementation, R-4.
**What:** `PhoneFrame.tsx`'s scan line animates unconditionally. It imports no `useReducedMotion` and
never has. The marketing `@media (prefers-reduced-motion: reduce)` block (`app/css/style.css:248`) is

block's own comment at `:244-247` asserts the demo's inline animations are "self-gated via
`useReducedMotion`", which is false for this one.
**Why deferred:** pre-existing, not created here; U8.2's row moves colour, not motion; and the honest
fix touches `app/css/style.css`'s comment (marketing, outside every U8 file list) as well as
`PhoneFrame`. Gating it is also not free — the sweep is the frame's only ambient motion and removing
it under reduce is a visual-design call, not a mechanical one.
**Trigger:** **U8.4** (the design-sync/shell package, which already holds `PhoneFrame` and the
cross-cutting shell rows) gates the sweep on `useReducedMotion` and corrects the CSS comment — or, if
U8.4 does not take it, the next package that touches `PhoneFrame.tsx`'s animation at all.

### Proposal C — A11/A12 (`grid`, `gridLight`) remain unported after U8

**Source:** U8.2 implementation, R-7.
**What:** two of the phone's three grid tokens have no web-side token after U8.2 and no package owns

**Trigger:** **the first demo surface that needs a second grid weight ports both in that surface's

## 6. Two likely defects

**1 · The reduced-motion gap is real and the CSS comment actively hides it.** Proposal B. Anyone
reading `app/css/style.css:244-247` will conclude the demo's inline animations are self-gated and stop
looking. They are, *except this one* — the largest and most persistent ambient motion on the page,
running behind every screen for the whole session. A reviewer checking "does the port respect
reduced-motion" against that comment gets a false green.

**2 · `teal-purge.test.ts`'s exemption is per-FILE, so a D12 file could regress inside its own row.**
The exemption key is `<path>:#4ecdc4` and canonicalises the value, so `StoryRail.tsx` may paint the
teal any number of times in any spelling. That is deliberate — the reason is per-file ("this surface
is outside the frame") and one row per occurrence would rot on every layout edit — but it means
`StoryRail` growing a *fourth* teal element is invisible, and so is one of its existing three losing
its teal while another keeps it. The stronger shape (an occurrence COUNT per file) was rejected as a
change-detector: it reds on any refactor of those files and protects nothing D12 cares about. Flagged
so the choice is reviewed rather than assumed. The inventory case does still catch a file entering or
leaving the set entirely, which is the failure mode D12 actually has.
