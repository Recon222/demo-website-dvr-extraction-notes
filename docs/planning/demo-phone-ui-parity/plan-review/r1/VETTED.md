**R-4 — V-4: ARCH-5's mechanism is correct; QUAL-4's is refuted. The finding survives on the half both lanes share.**
The lanes asserted incompatible consequences, so I ran the probe against this repo's actual jsdom (**29.1.1**):

```
background   "color-mix(in srgb, #2B8CC1 8%, transparent)" -> "color-mix(in srgb, rgb(43, 140, 193) 8%, transparent)"
borderColor  "color-mix(in srgb, #2B8CC1 8%, transparent)" -> "color-mix(in srgb, rgb(43, 140, 193) 8%, transparent)"
color        "color-mix(in srgb, #2B8CC1 8%, transparent)" -> "color-mix(in srgb, rgb(43, 140, 193) 8%, transparent)"
borderColor  "rgba(43,140,193,0.08)"                       -> "rgba(43, 140, 193, 0.08)"
```

jsdom **preserves** the declaration and normalises the hex to `rgb(...)`. So QUAL-4's *"any assertion reading a `withAlpha`-produced value would read `''` and pass vacuously"* is **wrong** — nothing is silently un-pinned. What actually happens is ARCH-5's version: existing assertions redden for a **format** change rather than a value change, which is noisy and muddies §4.4's RED/GREEN discipline, but is loud. **The load-bearing half is untouched by the probe and is why V-4 stays MAJOR:** `flattenOver` is a numeric compositor and cannot parse a `color-mix()` string, so every value the port deliberately routes through `withAlpha` becomes unmeasurable by gate 2 of §6.6 — the gate the same phase is building. One correction to ARCH-5's evidence: `rgba()` does **not** round-trip byte-identically (jsdom re-spaces it), which is why the demo's existing pins already go through a `hexToJsdomRgb`-style helper. The writer must not paste "byte-identical" into the doc.

**R-5 — V-26: QUAL-11 is half right. Keep the missing-list half, drop the contradiction half.**
